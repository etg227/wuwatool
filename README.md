# 鸣潮声骸评分器 / WuWa Echo Scorer

一个纯前端的《鸣潮》单角色声骸理论工具，独立部署于 **[wuwatool.etg227.com](https://wuwatool.etg227.com/)**。它采用双轨口径：

- **静态词条评分与毕业度**（学习 WuwaEchoTool）：按角色相关的固定系数衡量词条本身的质量，不随面板变化；
- **边际换装计算**：按玩家实时面板、共鸣链、武器/合鸣套装和角色伤害构成完整重算替换收益与可实现的提升建议。

方法定义、可复算示例与适用边界见配套文章[《鸣潮声骸评价的双层模型》](https://blog.etg227.com/2026/09/17/wuwa-echo-methodology/)。

## 当前功能

- **单角色模式**：不包含配队、队友 Buff 或输出窗口。
- **角色卡片选择**：角色名称和头像来自库街区《鸣潮》WIKI 角色目录快照；角色切换时会清空上一角色的面板、声骸和候选声骸。
- **角色机制库**：陆·赫斯及以前优先复用 WuwaEchoTool 已整理的数据，后续角色由本项目继续维护；前瞻/未正式校验角色会单独标记，不冒充正式服最终数据。
- **共鸣链 0–6**：已建模角色会自动读取对应链数带来的战斗态修正和伤害构成变化。
- **ATK / HP / DEF 倍率角色**：角色可按其主要倍率属性进行边际收益计算。
- **当前静态面板**：玩家只填写游戏角色详情页当前面板；`baseline-sync.js` 会把初次完整录入的“非声骸底座”锁定，之后修改声骸时让模拟面板随之变化。
- **角色档案面板**：选择角色后展示伤害构成占比、当前生效中的共鸣链 / 套装 / 专武修正、数据置信度与机制说明。
- **候选为空时的理论排行**：未填写候选副词条时，左侧结果区展示各词条在当前面板下的理论边际收益（平均档），作为词条价值参考。
- **完整合鸣套装数据库**：主套装会列出当前数据库中的全部套装。选择主套后再选择合法件数（5件 / 3件 / 特殊1件）；只有主套为3件时才能选择2件副套，5件时副套装锁定。
- **武器被动**：已校验的专武效果可自动计入。
- **5只声骸独立评分**：每个装备位可填写 COST、主词条与5条副词条，并分别计算静态词条评分与 SSS–D 评级。
- **固定档位下拉**：副词条数值只允许选择游戏内实际档位；4-COST 支持暴击、暴伤、攻/生/防和治疗效果主词条。
- **候选声骸替换**：指定替换1–5号声骸后，计算整套理论提升。
- **候选逐条贡献**：候选声骸每条副词条都会单独显示对当前角色的边际贡献。
- **可实现的提升建议**：推荐器只考虑“把已有词条提到满档”或“把某条现有词条替换为目标词条平均档”这两类游戏内真实可执行的动作，且**每个方案都克隆整套声骸完整重算**（暴击上限、套装阈值等边界都按该方案重新判定），不做比例近似。
- **输入合法性**：副词条数值锁定游戏真实档位；同一只声骸内副词条类型不可重复（与游戏规则一致，重复选择会被清空提示）；总 COST 超过 12 时显眼警告，结果标注仅供理论参考。
- **本机配置保存**：角色、共鸣链、面板、主/副套装结构与5只声骸都可保存在浏览器本地，方便反复比较。
- **ER 不强行换算伤害**：共鸣效率属于阈值属性，当前模型不会伪造固定 DPS 权重。

## 合鸣套装逻辑

主套装选择器始终列出数据库中的全部可用套装，然后根据该套装实际存在的效果开放合法件数：

```text
5件主套：
  主套 2件效果 + 主套 5件效果
  2件副套锁定，不参与计算

3件主套：
  主套 3件效果 + 副套 2件效果
  只有此时可选择2件副套

特殊1件：
  只应用该套装的1件效果
```

触发型效果按数据中定义的已触发/满层口径处理；如存在明确阈值（例如 ER ≥ 250%），会先检查条件再加入计算。

## 声骸词条评分与毕业度

评分口径学习自已开源停更的 [WuwaEchoTool](https://github.com/GQin404/WuwaEchoTool)（作者已公开说明项目数据可取用）：每类副词条有一个角色相关的**静态系数**——

```text
暴击 1.8 · 暴伤 0.9 · 主倍率属性% 1（防御 1.2）· 对应固定值小系数
类型伤（普攻/重击/技能/解放）= 0.9 × 该角色对应伤害占比
共鸣效率 0.5 · 对应属性伤害（主词条）1 · 无关词条 0

单条得分 = 词条数值 × 系数
单只声骸词条评分 = Σ副词条得分 / 该角色理论最优五条满档词条 × 100
```

- `100` = 五条互不重复的最优有效词条全部满档。
- 评分只依赖角色及其伤害构成，**不随面板或其他声骸变化**：改第二只声骸不会影响第一只的分数。
- 副词条允许按游戏中的实际行顺序录入，中间留空不影响评分。

**整套毕业度**把主词条、固定主词条和副词条全部计分，除以整套理论满配后给出 0–100 分与评价档位（同 WuwaEchoTool 口径）：

```text
>90 完美毕业 · >80 大毕业 · >70 中毕业 · >60 小毕业 · >50 接近毕业 · 其余 咸鱼一条
```

替换收益、候选逐条边际贡献与“可实现的提升排行”仍按当前面板的**真实边际收益**计算——这两套口径互补：静态分回答“这只声骸本身歪不歪”，边际分析回答“下一步换什么最赚”。

**重要**：词条评分不看你的实时面板，所以**高分声骸不一定是当前配装的更优替换**（典型例子：暴击率已接近 100% 时，满暴击词条的静态分依然很高，但边际收益趋近于零）。要不要换、换哪只，以“候选声骸替换提升”和“可实现的提升排行”这两个按面板完整重算的数字为准。界面在声骸面板下方也常驻这条说明。

## 替换计算

玩家填写的当前面板应对应当前已装备的5只声骸。录入完整后，工具会锁定非声骸底座。

替换第 `n` 只声骸时：

```text
候选状态 = 非声骸底座 + 其余4只当前声骸 + 候选声骸
替换收益 = CandidateFactor / CurrentFactor - 1
```

因此不需要玩家手动重算换装后的整套面板。

## 核心公式

```text
期望暴击乘区 = 1 + min(CR, 100%) × (CD - 100%)

伤害加成乘区
= 1 + 全局伤害加成 + 属性伤害加成 + 对应攻击类型伤害加成

Amplify 乘区
= 1 + 全局 Amplify

Factor
= 主要倍率属性 × 伤害加成乘区 × Amplify 乘区 × 期望暴击乘区
```

角色伤害由其机制库中的普攻 / 重击 / 共鸣技能 / 共鸣解放 / 其他伤害权重进行加权，而不是要求玩家手工填写“主要伤害类型占比”。

## 数据

- 角色目录：库街区《鸣潮》WIKI。
- 旧角色伤害构成、逐链构成表与评分基础：[WuwaEchoTool](https://github.com/GQin404/WuwaEchoTool)（GQin404，已开源停更，作者已公开说明项目数据可取用）；相关角色的 `sources` 字段均带该仓库引用。
- 新角色与新套装：继续结合库街区与仍在更新的社区数据源进行维护和交叉校验。
- 声骸固定副词条档位：按游戏实际档位维护。
- [`data/sonata-effects.json`](./data/sonata-effects.json)：当前合鸣套装效果数据库。
- [`data/character-mechanics.json`](./data/character-mechanics.json) / [`character-mechanics-extra.json`](./data/character-mechanics-extra.json)：角色机制与补充模型（逐角色 sources / confidence 字段记录来源与置信度）。
- 本仓库 `data/` 即主数据；角色目录快照由 CI（`update-characters`）每周自动刷新。

详细来源与公式说明见 [`REFERENCES.md`](./REFERENCES.md)。

## 库街区账号导入

`kuro-sync.js` 提供可选的库街区账号导入（接口调用方式学习自 WuwaEchoTool）：

1. 在角色配置面板展开“库街区账号导入”，粘贴库街区 token 并绑定（token 仅保存在当前浏览器 localStorage，直连 api.kurobbs.com 官方接口，本站不上传、不经手）。
2. 输入 9 位特征码 UID，点击“导入角色”读取该账号公开的角色列表。
3. 点击角色头像，自动填入角色、共鸣链和 5 只声骸的主/副词条（数值吸附到最近的合法档位）。
4. 面板数值（攻击/双暴/共鸣效率等）接口不提供，仍需照游戏内角色详情页填写。

注意：请勿在共享设备绑定 token；token 过期后重新绑定即可，也可随时“解绑”删除本地保存。若浏览器因跨域策略拦截请求，该功能会明确报错而不影响手动使用。
